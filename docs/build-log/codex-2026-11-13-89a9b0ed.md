npx --yes web-push generate-vapid-keys --json

Add these three values:

| Render variable | Value |
|---|---|
| `VAPID_PUBLIC_KEY` | The generated `publicKey` |
| `VAPID_PRIVATE_KEY` | The generated `privateKey` |
| `VAPID_SUBJECT` | `mailto:your-real-email@example.com` |

Paste the key values without surrounding quotes. The private key belongs only on Render. Nothing needs to be added to Vercel because FINN securely serves the public key from its API. Render recommends adding secrets through the service’s Environment page rather than committing them. [Render environment-variable instructions](https://render.com/docs/configure-environment-variables)

3. Choose **Save and deploy**. A rebuild is unnecessary because these are runtime variables.

4. After deployment, open:

```text
https://finn-api-mxni.onrender.com/api/push/config
```

It should return something like:

```json
{"available":true,"public_key":"..."}
```

It will never expose the private key.

5. Test from the deployed FINN app:

Keep a secure backup of the pair in your password manager. Avoid rotating it after people subscribe because subscriptions are tied to that application-server key.
