## How the app is made

FINN has a sound architecture:

```text
NSE / company IR / Yahoo
           ↓
Local or GitHub worker
           ↓
Rules + XBRL calculations + selective LLM extraction
           ↓
Postgres normalized data + materialized JSON views
           ↓
Read-only FastAPI
           ↓
Next.js mobile app
           ↓
Bundled snapshot when API/database is unavailable
```

The important implementation choices are:

- Push classifies and ranks filings using deterministic rules first; models handle the difficult remainder. About 79% are handled without a model.
- Results are calculated from XBRL rather than generated by an LLM.
- Pull reads transcripts and builds guidance chains: original promise → revision → actual → verdict.
- Model-extracted claims survive only if the quote is verifiably present in the transcript.
- Network recommendations use deterministic path/warmth/relevance scoring over 72 clearly labelled synthetic contacts.
- Arbitrary ticker research is queued through Postgres and executed by a laptop or GitHub Actions worker.
- The user-facing read path does not call models or exchanges, which makes it fast, inexpensive, and resilient.
- Alerts are evaluated locally, so threshold changes preview immediately.
- Model calls are cached and recorded in a cost ledger.

The best technical explanations are already in [ARCHITECTURE.md](</%USERPROFILE%/OneDrive/Desktop/enam-afe/docs/ARCHITECTURE.md>) and the product status is honestly tracked in [STATUS.md](</%USERPROFILE%/OneDrive/Desktop/enam-afe/docs/STATUS.md>).
